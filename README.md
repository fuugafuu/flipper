# FLIPFRAME STUDIO

Flipper Zero向けの動画・音声変換Webアプリ。メディアをブラウザ内で処理し、128×64／1-bitの映像と16kHzのIMA ADPCM音声（v2）、または従来の単音ブザー信号（v1）を `.fzmv` に保存します。PC・スマートフォンで変換前後の映像を比較し、変換後の映像と音声を同期再生できます。

## 起動と公開

```bash
npm install
npm run dev
npm run test
npm run build
```

Vercelでは Framework = Vite、Build = `npm run build`、Output = `dist` を指定します。ファイル変換はブラウザ内で行い、Webサーバーにアップロードしません。動画中の音声を抽出するときは同一オリジンで配信するFFmpeg WebAssembly（約30 MB）を初回に取得します。PCのブラウザでも、ファイルの形式やコーデックによっては読めないものがあります。

## 変換処理

- **映像**　画面アスペクト比の維持またはクロップ → 128×64縮小 → 映像領域内の輝度ヒストグラム分析 → 暗部の自動階調補正と時間方向の露出安定化 → コントラスト・輪郭強調 → Atkinson / Floyd–Steinberg / Bayer 8×8ディザリング → ちらつき抑制 → 1-bitビットパック。6〜60 FPSを選択できます。
- **圧縮**　2秒ごとのキーフレーム、フレームごとのRaw / RLE / XOR delta / XOR+RLEの最小サイズを選択。
- **高音質音声（初期設定）**　元のチャンネルをモノラルへ混合 → 16kHzにアンチエイリアス付きリサンプリング → 210Hz付近の高域通過・5.4kHz付近の低域通過で内蔵圧電素子の不得意帯域を緩和 → 音量正規化とソフトリミッター → 16bit波形 → 4bit IMA ADPCMの独立256サンプルブロックへ圧縮。単音化による音程の乱高下を回避し、声・楽器・リズムの波形を保持します。
- **従来の単音モード**　8kHzの信号を20ms間隔でFFT解析して主要な単音を選択。100〜2500Hzに限定し、従来のFZMV v1として保存します。
- **プレビュー**　コンテナから復号した実データを使って128×64液晶を描画。高音質モードはADPCM復号後の波形をWeb Audioの300Hz高域通過・4.6kHz低域通過フィルター経由で再生。単音モードは矩形波で近似。いずれも映像と同一のタイムラインで再生します。フィルターは圧電ブザーの帯域の目安で、実機の伝達特性を測定したものではありません。
- **変換範囲**　時間制限を設けず、動画・音声の先頭から最後まで変換。長い動画はメモリ使用量、容量、変換処理時間が大きくなります。

Flipper Zeroの公式ハードウェア仕様は、128×64白黒LCD（ST7567）、STM32WB55RG（64MHzアプリケーションコア、256KB RAM）、ブザー100〜2500Hzです。第三者のWAV Playerアプリでは内蔵の圧電素子からPCM波形を再生する実装例があります。ただし、新形式の映像・音声同時再生、DMA/PWM再生方式、および実機音質は次段階のFAP開発で検証する必要があります。

参照: https://docs.flipper.net/zero/development/hardware/tech-specs

参考実装: https://github.com/LTVA1/wav_player

## FZMV v1 / v2 バイナリー仕様（すべてリトルエンディアン）

ファイルは64バイトのヘッダー、フレーム位置索引、フレームデータ、音声イベントの順に並びます。すべてのオフセットはファイル先頭からの絶対位置です。

| Offset | Type | Meaning |
| --- | --- | --- |
| 0 | char[4] | `FZMV` |
| 4 | u16 | Version = 1（単音）または2（IMA ADPCM） |
| 6 | u16 | Header length = 64 |
| 8 | u16 | Width = 128 |
| 10 | u16 | Height = 64 |
| 12 | u16 | Video FPS |
| 14 | u16 | Audio tick duration = 20ms（v1）、0（v2） |
| 16 | u32 | Frame count |
| 20 | u32 | Audio tick count（v2では0） |
| 24 | u32 | Frame offset table start |
| 28 | u32 | Frame record data start |
| 32 | u32 | Audio data start（v2ではADPCMデータ開始位置） |
| 36 | u32 | Clip duration (ms) |
| 40 | u32 | v1ではbit 0 = 音声あり。v2では値2 = ADPCM音声 |
| 44 | u32 | File length in bytes |
| 48 | u32 | v1では0。v2ではsample_rate = 16000 |
| 52 | u32 | v1では0。v2ではsample_count（復元後の正確なサンプル数） |
| 56 | u16 | v1では0。v2ではcodec = 1（IMA ADPCM） |
| 58 | u16 | v1では0。v2ではblock_samples = 256 |
| 60 | u16 | v1では0。v2ではblock_bytes = 132 |
| 62 | u16 | Reserved = 0 |

**Frame index** はフレーム数×4バイトの`u32`配列。各値は対応するフレームレコードの先頭位置。

**Frame record** は`codec: u8`、`length: u16`、`payload: byte[length]`。codec 0は1024バイトのRaw、1はRawのRLE、2は前フレームとの差分XOR（1024バイト）、3は差分XORのRLE。最初のフレームは必ずRawまたはRLE。ビットマップは**行優先**でピクセル(0,0)から右方向へ1ビットずつ、左端ピクセルが最上位ビットです。1が濃色、0が明色。画面は128×64=8192ビット=1024バイト。

**RLE** は1バイトの命令とデータの繰り返し。命令の最上位ビットが1なら次の1バイトを`(命令 & 127)+1`回繰り返します。0なら続く`(命令 & 127)+1`バイトをそのままコピーします。展開結果は常に1024バイト。

**v1 Audio** は20ms刻みの4バイト固定長イベント。`frequency: u16`(Hz, 0=停止)、`gain: u8`(0–255)、`gate: u8`(0–100%, tick内の発音割合) の並びです。音声時刻は`audio_index * 0.020`秒です。

**v2 Audio** は `audioOffset` 以降に16kHzモノラル、4bit IMA ADPCM（独立ブロック）を連続格納します。各132バイトブロックは `predictor: i16 LE`（そのブロック最初のPCMサンプル）、`step_index: u8`（0〜88）、`reserved: u8`（0）、続いて255個の4bit差分を低位ニブル→上位ニブルの順でパックした128バイトのデータです。最後の未使用ニブルおよび未使用サンプルは0で埋めます。最終ブロックの有効PCMサンプル数は `sample_count` に従います。`sample_count / 16000`秒が音声長です。任意時刻へは `floor(sample_index / 256) * 132` をADPCMデータ先頭に足して、そのブロックから復号できます。Flipper上ではSDカードからブロック単位で読み、256サンプル（512バイト）のPCMバッファをPWM出力する実装を想定しています。

映像時刻は両バージョンとも `frame_index / fps` です。映像ストリームには1024バイト×2のビットマップバッファとRLEデコーダを利用できます。v2は過去のv1ファイルを読めるようWeb側のデコーダを後方互換にしています。v1のみ実装する再生アプリはv2に対応する必要があります。

## 既知の制約

- **Flipper Zero実機再生アプリ（FAP）は未実装・未検証**。`.fzmv` は本プロジェクトの独自形式で、現行の公式アプリから直接再生できません。v2音声の実機用PCM出力処理も未実装です。
- **内蔵スピーカーは圧電素子**であり、PCM波形に対応するFAPを用意した場合も、一般的なスマートフォンのスピーカーに近い音質は期待できません。ブラウザの音質、音量、ひずみは実機と一致していません。特に低音の再生能力が限られます。v1の単音モードは引き続き単音の制限があります。
- 動画の音声抽出でFFmpeg WebAssemblyが必要な場合、初回にネットワークアクセスと比較的多いメモリを使います。iPhoneなどの端末で長い動画を変換するとメモリ制限に達する場合があります。
- 動画の再生可否はブラウザの対応コーデックに依存します。長時間・高FPSではブラウザのメモリ制約で処理できない場合があります。FZMV v1のファイルサイズと尺はヘッダーの32ビット整数で表現できる範囲に限られます。
- **60 FPSでのエンコードとブラウザ表示は可能ですが、実機での60 FPS動作は未検証**。画面更新速度、microSD読込帯域、音声と描画の同時処理負荷は実機アプリ実装時に測定が必要です。10FPSを初期値にし、圧縮方式で転送量を減らしています。
