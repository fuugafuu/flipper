# FLIPFRAME STUDIO

Flipper Zero向けの動画・音声変換Webアプリ。メディアをブラウザ内で処理し、128×64／1-bitの映像と単音ブザー制御信号を `.fzmv` に保存します。PC・スマートフォンで変換前後の映像を比較し、変換後の映像とブザー音を同期再生できます。

## 起動と公開

```bash
npm install
npm run dev
npm run test
npm run build
```

Vercelでは Framework = Vite、Build = `npm run build`、Output = `dist` を指定します。ファイル変換はブラウザ内で行い、Webサーバーにアップロードしません。動画中の音声を抽出するときは同一オリジンで配信するFFmpeg WebAssembly（約30 MB）を初回に取得します。PCのブラウザでも、ファイルの形式やコーデックによっては読めないものがあります。

## 変換処理

- **映像**　画面アスペクト比の維持またはクロップ → 128×64縮小 → 映像領域内の輝度ヒストグラム分析 → 暗部の自動階調補正と時間方向の露出安定化 → コントラスト・輪郭強調 → Atkinson / Floyd–Steinberg / Bayer 8×8ディザリング → ちらつき抑制 → 1-bitビットパック。6〜60 FPSを選択できます。
- **圧縮**　2秒ごとのキーフレーム、フレームごとのRaw / RLE / XOR delta / XOR+RLEの最小サイズを選択。
- **音声**　8kHzのモノラル信号を20ms間隔でFFT解析し、複数の倍音、前回のピッチ、帯域の重みから主要な単音を選択。振幅エンベロープで音量を制御。100〜2500Hzに限定。
- **プレビュー**　コンテナから復号した実データを使って128×64液晶を描画。映像は60 FPSまで追従するアニメーションフレーム更新。Web Audioの矩形波＋フィルターでブザーを近似し、イベントを短い単位で予約して長時間再生時の負荷を低減。同一タイムラインから再生し、元動画との無音同期比較にも対応。
- **変換範囲**　時間制限を設けず、動画・音声の先頭から最後まで変換。長い動画はメモリ使用量、容量、変換処理時間が大きくなります。

Flipper Zeroの公式ハードウェア仕様は、128×64白黒LCD（ST7567）、STM32WB55RG（64MHzアプリケーションコア、256KB RAM）、ブザー100〜2500Hzです。

参照: https://docs.flipper.net/zero/development/hardware/tech-specs

## FZMV v1 バイナリー仕様（すべてリトルエンディアン）

ファイルは64バイトのヘッダー、フレーム位置索引、フレームデータ、音声イベントの順に並びます。すべてのオフセットはファイル先頭からの絶対位置です。

| Offset | Type | Meaning |
| --- | --- | --- |
| 0 | char[4] | `FZMV` |
| 4 | u16 | Version = 1 |
| 6 | u16 | Header length = 64 |
| 8 | u16 | Width = 128 |
| 10 | u16 | Height = 64 |
| 12 | u16 | Video FPS |
| 14 | u16 | Audio tick duration = 20ms |
| 16 | u32 | Frame count |
| 20 | u32 | Audio tick count |
| 24 | u32 | Frame offset table start |
| 28 | u32 | Frame record data start |
| 32 | u32 | Audio data start |
| 36 | u32 | Clip duration (ms) |
| 40 | u32 | Flags, bit 0 = audio present |
| 44 | u32 | File length in bytes |
| 48 | byte[16] | Reserved, zero |

**Frame index** はフレーム数×4バイトの`u32`配列。各値は対応するフレームレコードの先頭位置。

**Frame record** は`codec: u8`、`length: u16`、`payload: byte[length]`。codec 0は1024バイトのRaw、1はRawのRLE、2は前フレームとの差分XOR（1024バイト）、3は差分XORのRLE。最初のフレームは必ずRawまたはRLE。ビットマップは**行優先**でピクセル(0,0)から右方向へ1ビットずつ、左端ピクセルが最上位ビットです。1が濃色、0が明色。画面は128×64=8192ビット=1024バイト。

**RLE** は1バイトの命令とデータの繰り返し。命令の最上位ビットが1なら次の1バイトを`(命令 & 127)+1`回繰り返します。0なら続く`(命令 & 127)+1`バイトをそのままコピーします。展開結果は常に1024バイト。

**Audio** は20ms刻みの4バイト固定長イベント。`frequency: u16`(Hz, 0=停止)、`gain: u8`(0–255)、`gate: u8`(0–100%, tick内の発音割合) の並びです。映像時刻は`frame_index / fps`、音声時刻は`audio_index * 0.020`秒。再生にはファイルをストリーム読み込みし、1024バイト×2のビットマップバッファとRLEデコーダを使う構成を想定しています。

## 既知の制約

- **Flipper Zero実機再生アプリ（FAP）は未実装・未検証**。`.fzmv` は本プロジェクトの独自形式で、現行の公式アプリから直接再生できません。
- **ブザーは単音**です。複数音、ドラム、会話などの完全な音質再現はハードウェアの制限上できません。ブラウザの音は矩形波の近似であり、音量、音質、周波数変化の実機一致は未検証です。
- 動画の音声抽出でFFmpeg WebAssemblyが必要な場合、初回にネットワークアクセスと比較的多いメモリを使います。iPhoneなどの端末で長い動画を変換するとメモリ制限に達する場合があります。
- 動画の再生可否はブラウザの対応コーデックに依存します。長時間・高FPSではブラウザのメモリ制約で処理できない場合があります。FZMV v1のファイルサイズと尺はヘッダーの32ビット整数で表現できる範囲に限られます。
- **60 FPSでのエンコードとブラウザ表示は可能ですが、実機での60 FPS動作は未検証**。画面更新速度、microSD読込帯域、音声と描画の同時処理負荷は実機アプリ実装時に測定が必要です。10FPSを初期値にし、圧縮方式で転送量を減らしています。
